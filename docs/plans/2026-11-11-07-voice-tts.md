# Plan 6 — NPC voice (TTS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pirates speak their AI lines aloud: every NPC line in an AI dialogue (answers, openings sent by the Game Master,
farewells, fallback lines) is synthesized by a text-to-speech provider and played like an original voice line, with the
subtitle shown for as long as the audio lasts.

**Architecture:** A TTS provider interface in `aicore` (like `ILlmProvider`), with one real client for the OpenAI
`/audio/speech` endpoint (also served by local OpenAI-compatible TTS servers) and a mock. `GameSession` synthesizes the
NPC's answer in the same worker thread as the LLM call and returns the WAV bytes in `TurnResult`, so audio and subtitle
start together; fixed lines (farewells, fallbacks) are cached on disk. The engine only loads the WAV from memory into the
dialogue sound slot the original `AI_Output` uses. Voice is optional: `provider = off` (the default) changes nothing.

**Tech Stack:** C++20 + doctest + nlohmann::json (aicore), WinHTTP via the existing `IHttpClient`, Tempest `Sound` /
`SoundDevice` (engine), Markdown.

**Spec:** No separate design doc: the user asked for the plan directly (2026-11-11). The design decisions are in the
next section; docs/00 (non-goal "TTS next release"), docs/04 ("NPC speaks arbitrary text … TTS later") and docs/05
(configuration) are updated in Task 6.

## Design decisions (planner's calls, the user has not reviewed them yet)

1. **Provider:** OpenAI-compatible `POST {base_url}/audio/speech`, default model `gpt-4o-mini-tts`. The user already plays
   with an OpenAI key. The same endpoint is served by local servers (Kokoro-FastAPI, openedai-speech), which gives a free
   offline option. Anthropic has no TTS. ElevenLabs (best Polish quality, own API) is left for a later plan.
2. **Off by default.** `[tts] provider = off`. A broken or missing TTS config never blocks the game: the game shows
   subtitles only, with one hint.
3. **Own `[tts]` section**, with its own `base_url`, `model`, `api_key` and `timeout_s`. If `api_key` is empty and
   `base_url` equals `[ai] base_url`, the `[ai]` key is reused, so an OpenAI player adds two lines only.
4. **Audio before the subtitle.** An answer is shown only when both the text and the audio are ready (the NPC keeps
   "thinking" meanwhile). Showing the subtitle first and the sound later looks broken. The audio is not streamed: one
   short line takes about a second, which is acceptable for a first version.
5. **WAV only** (`response_format: "wav"`). Tempest decodes WAV and OGG from memory; WAV needs no decoder work. A reply
   that is not RIFF/WAVE is an error (`BadResponse`).
6. **One voice per pirate**: the card's `voice` field holds the provider's voice name and a style instruction (PL/EN) for
   `gpt-4o-mini-tts` `instructions` ("gruff, drunk old pirate captain…"). The OpenAI voice set has few male voices, so
   pirates share them; the instructions tell them apart.
7. **Who speaks:** NPCs only. The hero's typed line is not voiced (the original hero voice can't say arbitrary text,
   and a different voice for the hero would clash). Director `ambient_line` prints stay silent.
8. **Cache only fixed lines** (farewells, fallbacks) in `tts_cache/`, keyed by a hash of model + voice + style + text.
   AI answers are unique, so caching them would only fill the disk.
9. **Cost in the benchmark:** each TTS call is logged (latency, characters, audio ms, cost). `pricing.json` gets
   `tts.<model>.usd_per_minute` (an audio-minute estimate; the builder checks the current price list).

## Global Constraints
- Same as Plans 2–5: namespace `grog::ai`, `Result` errors and no throws across the API, UTF-8 inside aicore, tests first,
  engine hooks marked `// GROG:`, LF line endings, English in code/docs, README in both languages with the same content.
- The API key (also the TTS key) never appears in logs, hints, summaries, the cache or the aggregation output.
- Text sent to TTS is the UTF-8 original, never the cp1250 game text.
- `provider = off` or no `[tts]` section: no TTS request, no cache directory, behaviour identical to Plan 5.
- TTS never blocks the main thread: synthesis runs only in worker threads (`talkAsync`, `speakAsync`).
- Default TTS timeout: 15 s. On TTS failure the line is still shown, with subtitle timing from the text as today.

## Review Focus
1. TTS key wrong or quota exhausted while the LLM works: lines still appear on time as subtitles, one hint
   ("Głos: …/Voice: …") per error kind, no retry storm — Task 4.
2. A provider ignores `response_format` and returns MP3 (some local servers do): rejected as `BadResponse`, subtitles only, hint
   once — Task 2 (WAV check) + Task 4 (fallback path).
3. Very long AI answer (the model ignores "1–3 sentences"): the TTS input is capped at 600 characters and the subtitle
   stays readable for the full audio length — Task 2 (cap), Task 5 (timing).
4. The player presses Esc or "End" while audio plays, or loads a save mid-answer: the sound stops with the subtitle and a
   late audio result is discarded, never played over the next line — Task 5.
5. `provider = off` / no `[tts]` section in an old GrogAI.ini: config still parses, nothing is requested — Task 1.

### Task 2: TTS provider (OpenAI-compatible + mock) and WAV helpers

**Files:**
- Create: `aicore/include/grog/ai/tts.h`, `aicore/src/tts.cpp`
- Modify: `aicore/CMakeLists.txt` (add `src/tts.cpp`), `aicore/tests/CMakeLists.txt` (add `test_tts.cpp`)
- Test: `aicore/tests/test_tts.cpp` (uses `fake_http.h`)

**Interfaces:**
- Consumes: `TtsConfig` (Task 1), `IHttpClient`, `Result`, `ErrorKind`.
- Produces (tts.h):
  ```cpp
  struct TtsRequest { std::string text; std::string voice; std::string instructions; };
  struct TtsReply { std::string wav; double latencyMs = 0; int audioMs = 0; std::string model; };
  class ITtsProvider {
   public:
    virtual ~ITtsProvider() = default;
    virtual Result<TtsReply> synthesize(const TtsRequest& r) = 0;
    virtual std::string_view model() const = 0;
  };
  class MockTts : public ITtsProvider {  // returns a 100 ms silent 16-bit mono 24 kHz WAV
   public:
    std::deque<Error> scriptedErrors; std::vector<TtsRequest> requests;
    Result<TtsReply> synthesize(const TtsRequest& r) override; std::string_view model() const override { return "mock"; }
  };
  std::unique_ptr<ITtsProvider> makeTtsProvider(const TtsConfig& c, IHttpClient& http);  // nullptr for Off
  std::optional<int> wavDurationMs(std::string_view wav);   // nullopt if not a PCM RIFF/WAVE
  constexpr size_t kTtsMaxChars = 600;
  ```
- [ ] **Step 1: Write the failing tests:**
  - `openai tts request`: fake HTTP replies 200 with `MockTts`-style WAV bytes; the request URL is
    `https://api.openai.com/v1/audio/speech`, header `Authorization: Bearer sk-t`, body JSON
    `{"model":"gpt-4o-mini-tts","voice":"onyx","input":"Arr!","instructions":"gruff","response_format":"wav"}`;
    reply `audioMs == 100`.
  - `long text is cut at a sentence end within 600 chars`: input of 900 chars with a `.` at 550 → sent `input` ends at
    that `.` and has ≤ 600 chars; without any sentence end → hard cut at 600.
  - `empty instructions are not sent`: body has no `instructions` key.
  - `non-wav reply is a BadResponse error`: 200 with `ID3...` bytes → `ErrorKind::BadResponse`.
  - `http errors map like the llm client`: 401 → `Auth`, 429 → `RateLimit`, 500 → `Server`, network failure passes
    through; error messages contain no key.
  - `wavDurationMs`: 24 kHz 16-bit mono with 48 000 data bytes → 1000; truncated header → `nullopt`; chunk order
    `RIFF/WAVE/LIST/fmt/data` is handled (skip unknown chunks).
  - `makeTtsProvider returns nullptr for Off`.
- [ ] **Step 2: Run** `tools\dev\aicore.cmd` → fails to compile (`tts.h` missing).
- [ ] **Step 3: Implement** in `tts.cpp`; reuse `statusError(int, std::string_view)` from `llm.cpp`
  (declare it in `llm.h`, do not copy it); 400/404 map to `Config` there, which is right for a wrong TTS model too. Timing with `std::chrono::steady_clock`.
- [ ] **Step 4: Run** `tools\dev\aicore.cmd` → green.
- [ ] **Step 5: Commit** `feat(aicore): TTS provider (OpenAI-compatible) and WAV helpers`.

- [ ] **Step 1: `grogSay` with audio.** When `wav` is not empty: `Tempest::MemReader` over the bytes →
  `Tempest::Sound` → `currentSnd = soundDevice.load(sound)`, `currentSnd.play()` (the same slot and volume path as the
  original `aiOutput`); `current.msgTime = max(audio length + 300 ms, 1500)`. Without audio: today's text formula.
  The hero's own line keeps calling `grogSay` without audio.
- [ ] **Step 2: Openings and farewells wait for their audio.** Opening: `GrogHost` keeps `openingsUtf8[id]` next to

  `grog.pendingSpeech`; the tick shows the line when it is ready (subtitle + audio together), the same way
  `grog.pending` is handled. Farewell: `farewellAsync`, then `endAfter` once it has been said. With voice off: the
  current synchronous path, unchanged.
- [ ] **Step 3: Stopping.** Esc / "End" / dialogue close while `currentSnd` plays: stop it (`currentSnd = SoundEffect()`,
  as `skipPhrase` already does); an abandoned `pendingSpeech` is handed to `GrogHost::adopt`-style ownership so the
  future is not destroyed on the main thread (blocking). The `generation_` check in the session covers loads.
