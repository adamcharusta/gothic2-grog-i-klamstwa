# Plan 2 — AI core library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An engine-independent C++20 static library `aicore` (plus a terminal tool `grogai-cli`) that rolls a scenario, holds world state, builds actor/director prompts, talks to any AI provider, validates the AI's commands and logs everything — fully unit-tested without the game and without paid API calls.

**Architecture:** `aicore/` lives in the main repo (not in the engine fork) so it builds and tests in seconds on Linux CI; Plan 3 links it into the engine. Every outside dependency sits behind an interface: `IHttpClient` (WinHTTP on Windows, a stub elsewhere, a fake in tests), `ILlmProvider` (Anthropic, OpenAI-compatible, mock), `Clock`/`Rng` seeded explicitly. The game never trusts the model: replies are parsed into `Command`s, validated against `WorldState`, and only accepted ones are applied.

**Tech Stack:** C++20, CMake ≥ 3.16, nlohmann/json 3.11.3 and doctest 2.4.11 via `FetchContent` (pinned URLs + SHA256), WinHTTP (Windows), GitHub Actions (ubuntu-24.04 gcc for tests).

**Spec:** [docs/03-game-master.md](../03-game-master.md), [docs/01-story-and-scenarios.md](../01-story-and-scenarios.md), [docs/02-characters-and-world.md](../02-characters-and-world.md), [docs/05-ui-and-configuration.md](../05-ui-and-configuration.md), [docs/06-benchmark-and-testing.md](../06-benchmark-and-testing.md)

## Global Constraints

- Namespace `grog::ai`. Headers in `aicore/include/grog/ai/`, sources in `aicore/src/`, tests in `aicore/tests/`. 2-space indent, 120 cols (.editorconfig).
- No engine, Tempest or ZenKit includes in `aicore`. No exceptions cross the public API for expected failures: use `Result<T>` (`std::variant<T, Error>` wrapper with `ok()`, `value()`, `error()`).
- All randomness through `grog::ai::Rng` (own xoshiro256** + own `uniform(n)`); **never** `std::uniform_int_distribution` (not portable across stdlibs → seeds would differ between MSVC and gcc).
- API keys never appear in logs, `Error::message`, or `to_json` of any config. Tests assert this.
- Text is UTF-8 everywhere in `aicore`; code-page conversion is the engine's job (Plan 3).
- Data files: `mod/data/**.json`, each with `"schema": <int>`. Player-facing strings have `pl` and `en`.
- Default model ids: Anthropic `claude-sonnet-5-5`; mock provider id `mock`.
- Build/test: `cmake -S aicore -B build/aicore -G Ninja && cmake --build build/aicore && ctest --test-dir build/aicore --output-on-failure`. Locally on Windows via `tools/dev/aicore.cmd` (loads MSVC env).
- Every task ends with a work report in `work/` + INDEX row (AGENTS.md).

## Review Focus

1. A model reply that is not clean JSON (prose around it, ```json fences, trailing commas, truncated output) must degrade to a fallback line, never crash or apply partial garbage — test in Task 7.
2. The actor prompt must never contain the full truth (culprit / tankard location) unless that NPC's role legitimately knows it — test in Task 6.
3. The same seed must give the same scenario on MSVC and gcc — test in Task 4 (golden values checked in CI on Linux and locally on MSVC).
4. Provider errors (401 bad key, 429 rate limit, 5xx, timeout, no network) map to distinct `ErrorKind`s with player-safe messages and no key leak — test in Task 3.
5. Polish characters in player input and model output survive the whole pipeline byte-exact (UTF-8) — tests in Tasks 6 and 9.

### Task 3: HTTP and LLM providers

**Files:** `include/grog/ai/http.h`, `src/http_winhttp.cpp` (Windows), `src/http_stub.cpp` (other), `include/grog/ai/llm.h`, `src/llm_anthropic.cpp`, `src/llm_openai.cpp`, `src/llm_mock.cpp`, `src/llm_factory.cpp`, `tests/fake_http.h`, `tests/test_llm.cpp`, `tests/data/*.json` (recorded replies).

**Interfaces — Produces:**
- `struct HttpRequest { std::string url; std::vector<std::pair<std::string,std::string>> headers; std::string body; int timeoutS; }`, `struct HttpResponse { int status; std::string body; }`
- `class IHttpClient { virtual Result<HttpResponse> post(const HttpRequest&) = 0; }`; `std::unique_ptr<IHttpClient> makeHttpClient()`.
- `struct ChatMessage { enum Role { User, Assistant } role; std::string text; }`
- `struct LlmRequest { std::string system; std::vector<ChatMessage> messages; nlohmann::json replySchema; int maxTokens = 600; }`
- `struct LlmReply { std::string text; int inputTokens = 0; int outputTokens = 0; double latencyMs = 0; std::string model; }`
- `class ILlmProvider { virtual Result<LlmReply> complete(const LlmRequest&) = 0; virtual std::string_view id() const = 0; }`
- `std::unique_ptr<ILlmProvider> makeProvider(const ProviderConfig&, IHttpClient&)`; `MockProvider` with `std::deque<std::string> scripted` replies (and a default in-character line when empty).

Request shapes (exact):
- Anthropic: `POST {base}/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`; body `{model, max_tokens, temperature, system, messages:[{role,content}]}`; the JSON schema is passed as an instruction appended to `system` (portable across models); reply text = concatenated `content[].text`; usage `usage.input_tokens/output_tokens`.
- OpenAI-compatible: `POST {base}/chat/completions` (base already contains `/v1` when the provider needs it), header `Authorization: Bearer <key>` (omitted when key empty, e.g. Ollama); body `{model, temperature, max_tokens, messages:[{role:"system"},…], response_format:{type:"json_object"}}`; reply `choices[0].message.content`; usage `usage.prompt_tokens/completion_tokens`.

- [ ] Tests with `FakeHttp` (records request, returns canned response): exact URL/headers/body fields for both providers; Ollama-style empty key → no Authorization header; parse recorded replies; status 401 → `Auth`, 429 → `RateLimit`, 500/529 → `Server`, network failure → `Network`, timeout → `Timeout`, 200 with junk → `BadResponse`; no error message contains the key; mock returns scripted replies in order. RED → implement → GREEN.
- [ ] WinHTTP client: compiled on Windows only, verified manually by `grogai-cli` (Task 9). Commit `feat(aicore): http interface and LLM providers`.

### Task 4: Deterministic RNG and scenario roller

**Files:** `include/grog/ai/rng.h`, `src/rng.cpp`, `include/grog/ai/scenario.h`, `src/scenario.cpp`, `tests/test_rng.cpp`, `tests/test_scenario.cpp`, `mod/data/cast.json`, `mod/data/places.json`.

**Interfaces — Produces:**
- `class Rng { explicit Rng(uint64_t seed); uint64_t next(); uint32_t uniform(uint32_t n); template<class T> const T& pick(const std::vector<T>&); }` (xoshiro256** seeded by splitmix64; `uniform` by rejection sampling).
- `enum class ScenarioType { LostAtDice, Lost, Stolen, InHisHut }`; `enum class Role { Culprit, Witness, Liar, Gossip, Unaware }`
- `struct Clue { std::string id; std::string holderNpc; std::string fact; std::vector<std::string> pointsTo; }` (pointsTo = npc ids or `place:<id>`)
- `struct Scenario { uint64_t seed; ScenarioType type; std::string culprit; std::string motive; std::string tankardLocation; std::map<std::string, Role> roles; std::vector<Clue> clues; }`
- `struct Cast { std::vector<std::string> npcs; std::vector<std::string> places; std::vector<std::string> motives; }` loaded by `Result<Cast> loadCast(const nlohmann::json& cast, const nlohmann::json& places)`.
- `Scenario rollScenario(uint64_t seed, const Cast&)`; `bool isSolvable(const Scenario&, const std::set<std::string>& burnedNpcs)` (BFS from `greg` over clues whose holder is not burned, reaching the tankard holder/location).

Rules: culprit ≠ `greg` except `InHisHut` (culprit = `greg`, location `place:greg_hut`); `LostAtDice`/`Stolen` → tankard held by culprit; `Lost` → `place:<random place>`, culprit = finder or `""` if still lying there; generator emits clues so that **two node-disjoint paths** (except start/end) exist from Greg to the truth; 1–2 liars and 1 gossip among the rest.

- [ ] Tests: golden values — `Rng(42)` first three `next()` values equal hard-coded constants (computed once from the reference algorithm and pasted into the test); `uniform(7)` never ≥ 7 over 10 000 draws; same seed → identical scenario (`to_json` equal); 500 seeds: every scenario has culprit ≠ greg unless InHisHut, `isSolvable(s, {})`, and for every single non-greg npc `x` on a path `isSolvable(s, {x})`; all four types appear across 500 seeds. RED → implement → GREEN. Commit `feat(aicore): seeded scenario roller with solvability check`.

### Task 7: Reply parsing and command validation

**Files:** `include/grog/ai/commands.h`, `src/commands.cpp`, `tests/test_commands.cpp`.

**Interfaces — Produces:**
- `struct Command { std::string type; nlohmann::json args; }`
- `struct ActorReply { std::string speech; std::string gesture; std::vector<Command> actions; bool endDialog = false; }`
- `Result<ActorReply> parseActorReply(std::string_view modelText)` — tolerant: strips ```json fences, takes the first balanced `{…}` object, ignores unknown fields; `speech` required, trimmed to 400 chars on a UTF-8 boundary.
- `struct Verdict { Command command; bool accepted; std::string reason; }`
- `std::vector<Verdict> validate(const std::vector<Command>&, std::string_view speakerNpc, const WorldState&)` and `void apply(const std::vector<Verdict>&, std::string_view speakerNpc, WorldState&, int64_t gameTimeS)`.
- `bool breaksCharacter(std::string_view speech)` (case-insensitive list: "as an ai", "language model", "jako ai", "model językowy", "chatgpt", "claude", "openai", "anthropic").

Validation rules (docs/03): known command types only; `give_item` only if speaker holds the item (`itemHolder`); `greg_tankard` only if speaker is its real holder; `attitude` delta in [−2, 2]; `quest_entry` text ≤ 200 chars; `npc_knowledge`/`npc_goto`/`npc_fight_npc` only for known NPCs and named places; `spawn_monster` only from whitelist and when none active; `start_fight` only with the player; events beyond `eventsThisHour` limit (8) rejected.

- [ ] Tests (Review Focus 1): clean JSON; JSON inside prose and ```json fences; trailing commas → `BadResponse` (not crash); truncated JSON → `BadResponse`; missing `speech` → `BadResponse`; 1000-char Polish speech trimmed without splitting a multibyte char; each validation rule accepted + rejected case; `apply` moves `greg_tankard` to `player` on accepted give; rejected commands change nothing; `breaksCharacter` true for "Jako AI nie mogę" and false for "Ai, na Beliara!". RED → implement → GREEN. Commit `feat(aicore): tolerant reply parser and command validator`.
